## 一、为什么是它：对照三条硬标准

| 标准 | 满足情况 | 具体例子 |
|---|---|---|
| **有规则冲突** | 强 | 同一件事三家写法不同：thinking 开关（DeepSeek 要显式关 / 智谱是 thinking type / 百炼是 enable_thinking）；`tool_choice` 在思考模式下返回 400；缓存最小前缀 64 token（DeepSeek）vs 1024（OpenAI）；base_url 拼法不同（百炼结尾必须带 `/v1`，DeepSeek 不能带） |
| **有适用范围约束** | 强 | 哪些模型支持 function calling、哪些完全免费、哪些有视觉能力、上下文长度分档、免费模型并发只有 1 |
| **你能判断答案对错** | **决定性优势** | 你过去五天亲手实测了几乎所有这些：缓存 64 token 下限、`tool_choice` + thinking 的 400、高峰档翻倍、三家 tokenizer 差 11%、免费模型并发 1 |

第三条是别人拿不走的。**别人做 RAG 要为"标准答案是什么"发愁，你已经有一半答案在自己脑子里**——
5 天里跑出来的每个数字，都是一个现成的 golden 条目。

## 二、额外的三个好处

1. **不贴行业标签。** 你明确说过不想被局限在航空。这个语料跟求职方向（AI 应用工程师）完全一致，
   面试时讲的是"我做了一个 LLM 平台文档的 RAG"，不是"我做了一个航空规则的 RAG"。
2. **难例可以自动生成。** "三家里哪些支持 strict 模式？"这类跨文档对比问题是天然的难例，
   不需要人工硬想 120 条 golden set 里最费劲的那部分。
3. **语料会漂移，这反而是素材。** 平台文档经常更新，将来能讲"语料版本管理与漂移检测"——
   这是 RAG 生产化里真实存在但很少有人做过的问题。
