# 实验记录

> 一条规矩：**看文档不算产出，跑通才算**。每次改提示词/改配置，都要留下可复现的数字。
> 这个文件本身就是作品的一部分——面试时能证明"我会做对照实验，而不是拍脑袋调参"。

## 怎么记

| 项 | 写法 |
|---|---|
| **假设** | "我猜把 X 改成 Y 之后，Z 会怎么变" —— 是**预判**，不是问题 |
| **配置** | **只改一个变量**，其他全固定（这才是对照） |
| **观测** | 同一问题跑 2 组以上，记录指标 |
| **结论** | 假设成立/不成立 + **为什么**。没写原因的结论等于没结论 |

观测指标统一用 `/chat` 返回的：
`data.answer`、`data.tags`、`data.confidence`、`usage.completion_tokens`（成本）、`latency_s`、`retries_used`。

**铁律：一次只改一个变量，每组至少 3 个不同问题。** 否则结果无法归因。

---

## 2026-09-21 · 今日三条结论

1. **XML 标签分隔对 DeepSeek 基本无效** —— 它是 Claude 训练时的原生约定，换模型不吃这一套（详见实验 3）
2. **我的 `wrap_document()` 措辞有 bug** —— 输入本身是问题时，模型会回答"文档里没有答案"（详见实验 3 附）
3. **few-shot 确实有害，且有害方式很具体** —— 示例的**语气和立场**会把模型的客观回答带成迎合，confidence 从 0.9 掉到 0.6（详见实验 4）

### 实验 1 · 系统提示的写法（第 1 章）

**状态：无效，需重做。**

原因：两次调用同时改了问题（小猫→云）、`use_xml`（false→true）、`role`（无→幼儿教师），
三个变量一起动，结果差异无法归因到任何一个。

**重做要求**：固定问题**和**其他参数，只改 `prompts.py` 里的 `SYSTEM_DEFAULT`，跑 3 个不同问题。

### 实验 2 · 角色提示（第 3 章）

**状态：部分有效。**

同一问题 `小猫怎么叫？`，`use_xml=true`，只改 `role`：

| role | answer | confidence | tags |
|---|---|---|---|
| 无 | "根据提供的文档，无法回答…文档中没有答案" | 0.90 | 小猫/叫声/文档 |
| 幼儿教师 | "喵喵。" | 0.95 | 小猫/叫声/拟声词 |

**观察**：加了角色后，回答从"无法回答"变成直接给答案，且更简洁（"喵喵。"）。

**但要注意**：这个差异可能主要来自下面那个 bug 被绕过了，而不是角色本身的作用。
**需要补一组：有 role 但 use_xml=false**，才能把"角色"的效果单独剥离出来。

### 实验 3 · XML 标签分隔（第 4 章）★重点

**假设**：用 XML 标签把用户输入包起来（数据/指令分离），模型会更清楚边界，回答更准。

同一问题 `小猫怎么叫？`，`role=幼儿教师`，**只改 use_xml**：

| use_xml | answer | confidence | tags |
|---|---|---|---|
| true | "喵喵。" | 0.95 | 小猫/叫声/拟声词 |
| false | "小猫通常发出"喵喵"的叫声。" | 1.00 | 猫/叫声/动物 |

**结论：假设不成立。** 对 DeepSeek 而言，开不开 XML 几乎没有差异——
关掉时回答反而更完整（"小猫通常发出…"，比光秃秃的"喵喵。"信息量大），confidence 也更高。

**推论**：XML 分隔是 Claude 的原生约定（它训练时就用这套），**换到 DeepSeek 上收益不显**。
这提醒一件事：把 A 模型的最佳实践搬到 B 模型，必须实测，不能照抄。

#### ★ 附：测出来的一个真 bug

`role` 为空 + `use_xml=true` 时，模型回答：

> "根据提供的文档，无法回答小猫怎么叫，因为文档中只有问题'小猫怎么叫？'，没有给出答案。"

**这不是模型的错，是我 `prompts.py` 里 `DOC_TEMPLATE` 的措辞问题**：

```
请基于上面的 <document> 内容回答用户的问题。
```

当用户输入**本身就是一个问题**（而不是待检索的资料）时，"基于文档内容回答"
会让模型把问题当成"需要从中找答案的文档"，于是得出"文档里没答案"。

**修法**：措辞要分场景——
- RAG 场景（文档确实是资料）：保留"基于文档回答"
- 纯问答场景：改成"用户的问题如下，请直接回答"

这个 bug 是 W2 做 RAG 前必须修掉的，否则检索回来没答案时它会一本正经地胡说。

### 实验 4 · few-shot 什么时候反而有害（第 7 章）★今天的硬结论

**假设**：加示例能让回答更符合期望。

同一问题 `圣诞老人会在圣诞节给我带礼物吗`，只改 `examples`：

| 配置 | answer | confidence |
|---|---|---|
| 无示例 | "取决于你是否相信…从现实角度看是虚构人物，实际送礼的通常是家人" | **0.90** |
| 加牙仙示例<br>（"当然存在，亲爱的…"） | "会，只要你相信…把袜子挂好就行" | **0.60** |

**结论：假设不成立，而且有害得很具体。**

一个语气亲昵、立场迎合的示例，把模型从**客观两说**直接带成了**迎合确认**：
- 无示例时它说"实际送礼的是家人"（真话）
- 加示例后它说"会，只要你相信"（顺着示例的口气说）

**关键的量化证据**：confidence 从 **0.90 掉到 0.60**。
模型自己都更不确定了，措辞却更肯定——**这种"不确定但说得笃定"的组合，正是幻觉的温床**。

**有害性出现的条件**（这是今天最有价值的归纳）：
不是"示例越多越坏"，而是**示例的立场/语气与期望的回答风格冲突时**最坏。
模型会模仿示例的**口气**，而不只是采纳其中的事实。

**工程含义**：few-shot 不能当"万能调味料"随手加。
加之前先问：这个示例的语气，是不是我想要模型模仿的语气？
